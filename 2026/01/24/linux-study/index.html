一 SG90 舵机的开发

如下图所示，最便宜的舵机 sg90，常用三根或者四根接线，黄色为 PWM 信号控制用处：垃圾桶项目开盖用、智能小车的全比例转向、摄像头云台、机械臂等。

常见的有 0-90°、0-180°、0-360°。

1.1 接线说明

  • 红线：VCC (5V)
  • 棕线：GND
  • 黄线：PWM 信号线

1.2 控制转角

转角的控制，主要向黄色信号线“灌入”PWM信号。 PWM波的频率不能太高，50hz，即周期=1/频率=1/50=0.02s，20ms左右数据：不同的PWM波形对应不同的旋转角度，以20ms为周期，50hz为频率的PWM波，定时器需要定时20ms,关心的单位0.5ms, 20ms = 0.5ms * 40

1.3 linux的定时器

分析：实现定时器，通过itimerval结构体以及函数setitimer产生的信号，系统随之使用signal信号处理函数来处理产生的定时信号。从而实现定时器。
先看itimerval的结构体
setitimer()将value指向的结构体设为计时器的当前值，如果ovalue不是NULL，将返回计时器原有值。
which:三种类型
ITIMER_REAL //数值为0，计时器的值实时递减，发送的信号是SIGALRM。
ITIMER_VIRTUAL //数值为1，进程执行时递减计时器的值，发送的信号是SIGVTALRM。
ITIMER_PROF //数值为2，进程和系统执行时都递减计时器的值，发送的信号是SIGPROF。
很明显，这边需要捕获对应的信号进行逻辑相关处理 signal(SIGALRM,signal_handler);
返回说明：
成功执行时，返回0。失败返回-1

二 OLED 屏幕的点亮

如下图所示，最经典小巧的显示外设 0.96 寸 OLED 屏幕，常用四根接线（I2C 协议），SCL 和 SDA 为数据通信引脚。用处十分广泛：温湿度传感器数据监控、智能小车状态显示、网络 IP 地址回显、简易菜单 UI 等。
常见的有 I2C 接口（4针）和 SPI 接口（6针/7针），显示颜色一般分为纯白、纯蓝或顶部黄底部蓝的双色版本。

  • VCC：3V

2.4 终端实际操作

  • cd ~/hardwareSoft/：切换到我们的文件目录。
  • vi oled_demo.c：创建我们的项目文件。

在vi oled_demo.c打开文件以后，我们先点Esc,然后在下面输入 :set paste 按回车（Enter） 再输入i 进入全局粘贴模式

右键空白处点击paste粘贴我们的oled_demo.c代码

  • gcc oled_demo.c -lwiringPi -o a.out：编译程序并链接 wiringPi 库。
    这里我们使用 gcc 编译器来把写好的 C 语言源码变成机器能运行的程序。
    其中 -lwiringPi（注意前面是小写的 L）非常关键，它的作用是告诉编译器去链接系统的 wiringPi 硬件控制库（因为代码里用到了它的 GPIO 引脚控制功能）；-o a.out 则是指定最终生成的可执行文件名字叫 a.out（你也可以把它改成 -o oled_demo 这样更具辨识度的名字）。
  • sudo ./a.out /dev/i2c-3：以管理员权限运行程序，并指定I2C设备。
    这是最后一步，执行我们刚刚编译好的 a.out 程序。因为直接操作硬件（I2C总线）通常需要管理员权限，所以必须在命令前加上 sudo。命令最后的 /dev/i2c-3 是一个传递给程序的参数，它会告诉程序具体要去使用哪一个I2C设备节点，这个值会被我们C代码里的 main 函数接收到。

三 OLED 屏幕命令行终端显示

3.1 终端1实际操作

  • cd ~/hardwareSoft/：切换到我们的文件目录。
  • vi oled_demo.c：创建我们的项目文件。

在vi oled_demo.c打开文件以后，我们先点Esc,然后在下面输入 :set paste 按回车（Enter） 再输入i 进入全局粘贴模式

右键空白处点击paste粘贴我们的oled_demo.c代码

  • gcc oled_demo.c oled.c font.c -o oled_mirro：编译OLED镜像程序。
    这里我们使用 gcc 编译器，将所有相关的源文件（主程序 oled_demo.c、OLED驱动 oled.c、以及字体数据 font.c）一次性编译成一个可执行文件。-o oled_mirro 则是我们为这个新程序指定的名字，意为“OLED镜像”，比默认的 a.out 清晰得多。
  • sudo ./oled_mirro：执行我们的编译文件。

3.2 终端2实际操作

  • exec > >(tee -a /tmp/oled_p) 2>&1：将终端所有输出“镜像”到临时文件。
    这是一条高级 Shell 指令。它的作用是把当前终端之后产生的所有输出内容（包括标准输出和错误信息）统统重定向一份到 /tmp/oled_p 这个临时文件中。配合我们之前编写的 oled_mirro 程序读取该文件，就能实现你在终端敲什么、看到什么，OLED 屏幕上就同步显示什么的效果。

四 TFT 屏幕部署 LVGL

如下图所示，这是一块显示效果非常惊艳的 1.69 寸彩色 TFT 屏幕。它采用 SPI 通信协议，分辨率高达 240x280。比起之前的 OLED 屏幕，它能提供更丰富的色彩和更高的像素密度，是运行 LVGL 图形库的最佳搭档。

4.1 接线说明

  • VCC：VCC(GPIO 1)
  • GND：GND(GPIO 9)
  • SCL：SCLK.1(GPIO 23)
  • SDA：MOSI.1(GPIO 19)
  • RES：PC9(GPIO 73)
  • DC ：PC6(GPIO 70)
  • CS ：PC7(GPIO 22)
  • BLK：PC5(GPIO 69)

4.2 下载到本地PC并上传lvgl_demo.zip

点击下载 LVGL 演示项目源码 (ZIP)
  • unzip lvgl_demo.zip：解压我们的文件夹。

4.3 fbtft驱动挂载和识别

在加载驱动前，我们需要确认自己的屏幕芯片是否在 fbtft 的支持列表中。

  • 官方支持列表：点击查看 fbtft 支持的所有 LCD 模块清单

  • sudo modprobe -r fbtft_device：移除内核中的 fbtft 驱动模块
    modprobe 是 Linux 用于管理内核模块的指令，参数 -r (remove) 表示卸载。由于 TFT 屏幕通常通过 fbtft_device 映射到系统的 Framebuffer（/dev/fbX），在修改屏幕旋转方向或切换驱动程序前，必须先执行此命令来释放占用的 GPIO 和 SPI 引脚，防止驱动冲突导致屏幕黑屏或显示异常。

挂载我们的屏幕驱动

屏幕设备识别

  • ls /dev/fb*：查看帧缓冲（Framebuffer）设备节点
    执行此命令是为了确认 TFT 屏幕驱动是否加载成功。在 Linux 系统中，显示设备被映射为 /dev/fb 开头的文件。通常 fb0 是系统默认显示器（如 HDMI），而我们驱动的 TFT 小屏通常会显示为 fb1 或 fb2。只有在这里看到了对应的节点，LVGL 才能通过这个接口向屏幕“画图”
