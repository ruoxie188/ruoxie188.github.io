Ubuntu 22.04 LTS使用docker部署openclaw,并接入飞书

本篇将手把手详细讲述如何在Ubuntu 22.04使用docker部署openclaw,并接入飞书

目录

  1. Docker 部署 OpenClaw
  2. 接入大模型
  3. 接入飞书机器人

一 Docker 部署 OpenClaw

1.1 获取 OpenClaw 源码与环境准备

  • mkdir -p ~/openclaw-dev/workspace：创建并进入工作目录。
    我们先在用户目录下创建一个名为 openclaw-dev 的专用文件夹。这样可以保持项目文件的整洁，避免和之前的 Linux 学习资料混在一起。
  • export http_proxy=...：为当前终端设置网络代理。
    由于国内连接 GitHub 有时速度较慢或连接失败，我们需要配置局域网内的代理服务器。注意：这个设置只在当前这个终端窗口生效，如果你关了重开，需要重新输入一遍。这里要注意后面的代理填写你自己的，如果没有代理用镜像网站下载源码也可以。
  • git clone ...：克隆 OpenClaw 源码到本地。
    这一步是从 GitHub 官方仓库将完整的项目代码拉取到本地，并存放进 source-code 文件夹中。如果你之前配置了代理环境，这一步下载的速度会非常快，不会一直卡在 0%。
  • ls -l source-code：检查文件夹内容是否完整。
    代码克隆完后，我们习惯性地用 ls -l 查看一下 source-code 文件夹内的文件列表。如果能看到像 docker-compose.yml 或者 README.md 这样的文件，说明源码已经成功下载到本地，可以准备进行下一步部署了。
  • vi Dockerfile：创建我们的项目文件。
    这里的话vi是采用linux自带的vim编辑器，vim编辑器刚开始用起来可能不习惯，用久会发现挺方便的。

在vi Dockerfile打开文件以后，我们先点Esc,然后在下面输入 :set paste 按回车（Enter） 再输入i 进入全局粘贴模式

右键空白处点击paste粘贴我们的Dockerfile代码

1.2 构建镜像并且启动容器

  • sudo docker build -t openclaw-custom .：构建并生成本地镜像。
    这一步是让 Docker 根据当前目录下的 Dockerfile 配置文件，把 OpenClaw 的源码和运行环境打包成一个叫 openclaw-custom 的镜像。注意命令最后的那个点 .，它代表在当前文件夹下查找配置，千万不能漏掉。
  • sudo docker run -it ...：正式启动并运行 OpenClaw 容器。
    这是让程序真正“活”起来的关键命令。-p 18789:18789 是将容器内部的端口映射到主机的 18789 端口，方便后续访问；-v 参数则是将本地的 workspace 文件夹挂载到容器内部，这样所有的配置文件和聊天记录都会保存在本地，即使容器删了数据也不会丢失。
  • ⚠️ 特别注意事项：请勿关闭当前终端，确保容器持续运行。
    由于我们在启动命令中使用了 -it 参数（交互模式），OpenClaw 此时是在前台运行的。如果你直接关闭这个终端窗口或按下 Ctrl + C，容器会立即停止。请务必保持这个窗口处于开启状态，因为接下来的“二 接入模型”和“三 接入飞书”的所有配置指令，都必须在容器正常运行的过程中才能实时生效并进行功能调试。

二 接入模型

2.1 注册并登陆MiniMax,并获取API密钥

在 OpenClaw 部署完成后，我们需要为它接入一个“大脑”。这里我们选择接入目前国产大模型中表现非常出色的 MiniMax（海螺 AI），新用户有15元的免费额度。

  • 访问 MiniMax 开放平台：注册并登录开发者账号。
    首先点击 MiniMax 开放平台官网 进行注册。目前 MiniMax 的模型（如 abab 系列）在逻辑推理和对话流畅度上非常优秀，是接入 OpenClaw 的极佳选择。

  • 创建 API Key：获取模型调用凭证。
    登录后台后，找到“账户管理”或“API 密钥”页面，点击创建一个新的 Key。请注意： 这串以 sk- 开头的密钥是 OpenClaw 调用大模型的唯一凭据，请务必妥善保管，不要泄露。

2.2 配置OpenClaw模型API

  • openclaw configure：启动 OpenClaw 交互式设置界面。
    在刚才保持开启的终端窗口中，输入这个命令。它会弹出一个非常友好的菜单，带你一步步完成“大脑”的联网设置。在这里，我们可以直接输入刚刚从 MiniMax 拿到的 API Key、模型名称以及 Base URL。相比于手动去修改复杂的 YAML 配置文件，这个交互式方法不仅效率高，而且不容易出错，非常适合新手。

  • 使用上下键选择本地（Local）回车：设置网关（Gateway）的运行位置。
    在执行 openclaw configure 后，第一个弹出的问题是询问网关（Gateway）运行在哪里。由于我们刚才已经通过 Docker 在这台机器上启动了服务，所以这里直接用键盘方向键选择第一个 Local (this machine) 并按回车（Enter）。这样 OpenClaw 就会默认通过本地地址 127.0.0.1:18789 来进行内部通信。
  • 使用上下键选择 Model 选项并回车：进入模型提供商与凭据（Credentials）配置界面。
    在主配置菜单中，我们需要通过上下键选中 Model。这一项是整个 OpenClaw 的“灵魂”，负责对接 AI 模型。选中它并按回车后，系统会进一步询问你使用的是哪家 AI 提供商（比如 MiniMax 或 OpenAI），以及你刚才在网页后台拿到的那串 sk- 开头的 API 密钥。
  • 使用上下键选择 MiniMax 选项并回车：确定模型提供商（Model Provider）。
    因为我们刚才在 MiniMax 官网注册并拿到了 Key，所以这里直接在列表中选中 MiniMax。OpenClaw 的配置非常智能，如果你是用的 DeepSeek、OpenAI 或者其他的国产模型，就在这里对应的选上就行。选定后，程序会自动加载适合 MiniMax 的参数模板。
  • 选择 MiniMax API key (CN) 并回车：确定认证方式与连接端点。
    这一步是选择连接 MiniMax 服务的认证方式。为了获得最佳的连接速度和稳定性，我们选择通过 API key (CN)（国内节点）进行连接。目前 MiniMax 的 M2.5 系列模型性能和对话效果都非常出色，选择这个国内端点（api.minimaxi.com）可以有效避免网络延迟带来的卡顿。

  • 输入 MiniMax API 密钥并回车：填入调用凭证完成身份认证。
    这一步我们需要把之前在 MiniMax 开放平台后台获取的那串以 sk- 开头的密钥复制并粘贴进来。在终端里，你通常可以通过点击鼠标右键或者按 Shift + Insert 来完成粘贴。这是大模型识别开发者身份的唯一凭证，填入后 OpenClaw 就能成功连接上 MiniMax 的服务器开始对话了。

直接按回车Enter

选择continue,再按回车

🎉 模型连接成功！
至此，我们的模型 API 配置就彻底完成了。现在，OpenClaw 已经成功获得了 MiniMax 的“大脑”支持。后续我们就可以通过 OpenClaw 来调用 MiniMax 模型进行各种智能任务的处理了。

三 接入飞书

3.1 访问飞书平台创建机器人

在配置好模型“大脑”后，我们需要给 OpenClaw 找一个互动的窗口。飞书机器人是一个非常完美的方案，它支持丰富的消息格式，且配置流程标准，是目前实现移动端 AI 交互的首选。

  • 访问飞书开放平台：注册并登录开发者账号。
    首先点击 飞书开放平台官网。这里是所有飞书机器人和自动化工具的“控制中心”。你需要使用自己的飞书账号登录，并进入右上角的“控制台”界面，我们接下来的所有应用创建和权限配置都将在这里完成。

  • 创建自建应用：开启你的机器人开发之旅。
    在开发者后台点击绿色的“创建自建应用”按钮。为你的机器人起一个响亮的名字（如：OpenClaw_Bot），并上传一个好看的图标。创建成功后，系统会自动为你生成 App ID 和 App Secret，这两串字符就是机器人的“身份证号”，请务必妥善保存。

  • 填写机器人名称

  • 选择“添加应用能力”：为自建应用开启机器人功能模块。
    在应用管理详情页的左侧菜单中，找到并点击 “添加应用能力”。在弹出的选项卡中选择“按能力添加”，在列表中找到 “机器人” 选项并点击右侧的“添加”按钮。这一步是赋予应用对话能力的“总开关”，只有开启了机器人功能，OpenClaw 才能通过飞书的 IM 接口实现消息的实时收发。

  • 点击“批量导入/导出权限”：一键配置机器人必备的各项功能权限。
    在权限管理页面，由于飞书的细分权限非常多，手动一个一个勾选既费时又容易出错。我们直接点击右侧的“批量导入/导出”，在弹出框里选择“导入权限”。这一步是确保 OpenClaw 能够正常“听见”用户说话（读取消息）、“回复”消息（以应用身份发送消息）以及处理图片和文件的核心前提。

  • 导入下面的JSON

  • 创建并发布初始版本：激活应用功能以解锁后续配置。
    在飞书后台的左侧菜单中，找到并点击 “版本管理与发布”。点击“创建版本”，填入一个版本号（例如 1.0.0），并简单写一下版本说明。请注意： 飞书的逻辑是“先发布，后生效”。虽然我们后面可能还会修改权限或回调地址，但必须先发布这个初始版本，飞书才会允许我们开启下一步的“事件订阅”功能。自建应用通常在点击“申请发布”后会立即通过审核。

  • 随意填写，保存发布即可

  • 进入“凭证与基础信息”页面：获取并记录 App ID 与 App Secret。
    在飞书开发者后台的左侧导航栏中，点击 “凭证与基础信息”。这里展示了该自建应用最核心的两个身份凭据：App ID（应用唯一标识）和 App Secret（应用密钥）。你可以把它们理解为机器人的“账号”和“密码”。OpenClaw 必须持有这两个凭证，才能代表这个自建应用合法地接入飞书服务器。请点击右侧的复制按钮，将这两串字符暂时记录在记事本中，我们马上就要在终端配置里用到它们。

  • 进入“机器人”页面：机器人自定义菜单
    这个一定要配置，你电脑端和手机端的飞书才能够给机器人发送消息，点击 “开启”

  • 随意填写，保存即可

3.2 配置 OpenClaw 飞书接口通道

  • openclaw configure：再次启动 OpenClaw 交互式设置界面。
    为了把刚才在飞书后台拿到的“钥匙”交给 OpenClaw，我们需要再次执行这个命令。虽然菜单看起来一样，但这次我们的重点是配置“通道（Channels）”。这个交互式界面会指引我们将飞书的 App ID、App Secret 以及验证令牌（Verification Token）准确地填入系统，实现程序与飞书服务器的正式对接。

  • 使用上下键选择本地（Local）回车：设置网关（Gateway）的运行位置。
    在执行 openclaw configure 后，第一个弹出的问题是询问网关（Gateway）运行在哪里。由于我们刚才已经通过 Docker 在这台机器上启动了服务，所以这里直接用键盘方向键选择第一个 Local (this machine) 并按回车（Enter）。这样 OpenClaw 就会默认通过本地地址 127.0.0.1:18789 来进行内部通信。
  • 使用上下键选择 Channels 选项并回车：进入消息通讯通道配置界面。
    这是配置飞书的最关键入口！在主菜单中，我们要通过上下键选中 Channels。这里的“通道”指的就是 OpenClaw 接收和发送消息的途径。选中并回车后，我们就可以在里面添加 Lark（飞书的海外版名称，配置通用）作为我们的主通讯方式，并填入之前准备好的 App ID 等凭据。
  • 使用方向键选择 Feishu/Lark 并回车：确定消息通讯的具体平台。
    进入通道选择菜单后，你会看到 OpenClaw 支持极广的平台列表（如 Telegram、Discord 等）。因为我们要对接的是国内的飞书，所以通过方向键向下滚动，找到 Feishu/Lark (飞书) 这一项。这里的“Lark”是飞书的海外版名称，在 OpenClaw 中它们共用同一套逻辑插件。选中它并回车，程序就会加载飞书专属的配置模板，准备让你填入 App ID 等信息。
  • 直接按 回车 (Enter) 确认选择第一个选项：Enter App Secret。

  • 输入飞书应用的 App ID 和 App Secret：填入关键的应用凭据完成身份验证。
    这一步我们需要将刚才在飞书开发者后台“凭证与基础信息”页面复制的两串字符分别粘贴进来。App ID 是应用的唯一身份证号，而 App Secret 则是对应的安全密钥。有了这两项信息，OpenClaw 才能代表你创建的那个机器人合法地登录飞书服务器，并获得发送和接收消息的权限。粘贴时请仔细核对，确保没有多余的空格。
  • 选择中国站点 (Feishu (feishu.cn) - China) 并回车：确定飞书服务器的区域域名（Domain）。
    由于我们是在飞书国内版官网（open.feishu.cn）创建的应用，所以这里必须选择第一个 Feishu (feishu.cn) - China。这决定了 OpenClaw 后续请求 API 时指向的服务器地址。如果选错成了国际版（Lark），会导致刚才填入的 App ID 和 Secret 无法被正确识别，提示鉴权失败。选定后按回车，程序将自动完成服务器区域的适配。
  • 选择 Open 选项并回车：设置群聊响应策略为开放模式（Open）。
    这一步决定了机器人在群聊中的表现。选择 Open - respond in all groups (requires mention) 后，只要有人在任何群聊中将机器人拉入群组并 @ 提及（Mention） 它，它都会自动给出回应。这种设置最为灵活，省去了手动配置繁琐“白名单（Allowlist）”的麻烦，非常适合日常办公交流或小团队协作。如果你希望它在所有群里都能随叫随到，选这一项准没错。
  • 选择 Finished (Done) 选项并回车：完成通道添加并确认当前配置列表。
    在你成功填入飞书的 App ID、Secret 等各项参数后，系统会再次把你带回到这个通道选择列表。由于我们目前只需要配置飞书这一个通讯平台，所以这里不再继续添加其他选项，而是直接使用方向键找到最底部的 Finished (Done) 并按回车。这一步表示你已经完成了对所有通讯渠道的设定，准备返回到最开始的主菜单进行最后的全局保存。
  • 使用方向键左右，选择 Yes 并回车：进入私聊访问策略（DM access policies）配置界面。
    这一步是决定机器人私聊权限的安全设置。由于机器人接入了 AI 模型（会产生费用），为了防止陌生人随便拉你的机器人进行对话导致额度被刷爆，系统会询问你是否要配置私聊策略。选择 Yes 后，你可以进一步设定它是“公开模式（Public）”还是“配对模式（Pairing）”。建议在这里选择 Yes，这样你可以更精细地控制谁有权在私聊窗口使用你的 AI 助手。
  • 直接选择 WebSocket (default)然后按回车这个有弹出来就选择，没弹出来不需要管,下面的配置也是。

  • 使用上下键选择 Pairing 选项并回车：设置私聊策略为推荐的“配对模式（Pairing）”。
    由于我们接入的大模型 API 是按量计费的，为了安全和省钱，建议在这里选中 Pairing (recommended)。这种模式非常巧妙：当陌生人在飞书上私聊你的机器人时，它不会立刻理人，而是需要你进行一个简单的“配对”确认。相比于完全公开（Open）或者死板的白名单（Allowlist），配对模式既保证了你的钱包安全，又保留了未来给朋友或同事使用的灵活性，是官方最推荐的平衡方案。
  • 选择 Continue (Done) 选项并回车：保存所有配置并正式退出设置向导。
    这是整个交互式配置流程的最后一步。在完成了模型（Model）、网关（Gateway）以及飞书通道（Channels）的所有细节填报后，我们通过方向键选中最底部的 Continue (Done) 并按下回车。这一步会将你刚才在终端里辛苦输入的所有 API Key、App Secret 以及各项策略设置正式写入到配置文件中并立即生效。执行完这一步后，终端会退出配置界面并回到正常的命令行状态，说明 OpenClaw 的后台系统已经完全“武装完毕”，随时准备上线服务了。

  • 选择“使用长连接接收事件”：开启免公网 IP 的即时通讯模式。
    在飞书开发者后台左侧找到 “事件订阅” 页面，在顶部勾选 “使用长连接接收事件”。这种模式的巨大优势在于：它不需要你拥有公网 IP，也不需要配置复杂的 Webhook 域名和 SSL 证书。只要你的 OpenClaw 容器正在运行且能够联网，飞书就能通过这条“长连隧道”把消息实时推送到你的本地服务器上。

  • 添加事件：im.message.receive_v1：赋予机器人“听取”消息的能力。
    点击下方的“添加事件”按钮，在弹出的列表中搜索并选择 im.message.receive_v1（接收消息 v2.0）。这是机器人的“耳朵”，只有添加了这个事件，当你在飞书里对机器人说话时，飞书服务器才会知道需要把这些内容转发给 OpenClaw 处理。

  • 点击“创建版本”：进入应用功能的正式发布流程。
    在左侧菜单栏找到 “版本管理与发布”，点击右上角的“创建版本”。这一步是把我们之前辛苦配置的权限、机器人开关以及 WebSocket 长连接等所有设置正式“打包”并推向线上的关键动作。

  • 填写版本号与更新说明：设定版本的唯一标识。
    在弹出页面中填入一个版本号（例如 1.0.0），并在更新说明里随便写点内容（比如“首次上线”或“更新事件订阅”）。这些信息主要是为了方便你自己以后管理应用时查看，不会影响机器人的运行。

  • 点击“保存”并确认发布：正式激活机器人服务。
    将页面拉到最下方，点击蓝色的 “保存” 按钮。保存成功后，系统会弹出一个申请发布的确认框，直接点击 “申请发布” 即可。对于自建应用，飞书通常会自动通过审核。一旦显示“已启用”，你的机器人就彻底“活”过来了，你现在就可以在飞书 App 里搜索并调戏它了！

  • 点击“打开应用”：正式进入对话界面并开启智能交互。
    当你在飞书后台成功发布新版本后，你的飞书客户端（无论是手机端还是电脑端）会立刻收到一条来自该应用的官方通知提醒。点击提示框下方的 “打开应用” 按钮，系统就会自动为你跳转到与该机器人的私聊对话窗口。这是见证奇迹的时刻：试着给它发一条简单的消息（例如：“你好，你是谁？”），如果它能流畅地利用 MiniMax 的强大智慧给你回复，那就说明你的 OpenClaw 已经彻底部署成功并正式上线服务了！

3.4 完成最后的身份配对 (Pairing)

由于我们在安全设置中开启了“配对模式”，机器人第一次收到你的私聊时会进行身份确认。

  • 给机器人发送“你好”：触发私聊配对申请。
    打开飞书，找到你刚创建的机器人并发送一句“你好”。此时机器人不会立刻回答你的问题，而是会识别出你是一个“新面孔”，并自动生成一条专属的授权指令发回给你（例如：openclaw pairing approve feishu XXXXXX）。这是 OpenClaw 的安全保护机制，确保只有经过你授权的账号才能使用 AI 额度。

  • 将配对指令发送到终端：完成身份绑定与正式授权。
    复制机器人发给你的那串以 openclaw pairing 开头的完整指令，回到你正在运行 OpenClaw 的终端窗口中，直接粘贴并回车执行。这一步相当于告诉程序：“这个飞书账号是我的，请允许它和我聊天”。执行成功后，终端会提示配对完成。现在，你可以尽情地在飞书里调教你的 AI 助手了！

🎉 飞书连接成功！
至此，我们的 OpenClaw 部署与飞书集成工作就彻底圆满完成了。现在，你已经可以随时随地在手机或电脑端打开飞书，搜索并调戏你的 AI 助手了。无论是处理复杂的逻辑任务，还是日常的闲聊问答，它都会利用 MiniMax 的强大“大脑”为你提供精准的服务。

  • ⚠️ 关键提醒：确保后台程序（Docker 容器）持续运行。
    虽然你现在可以在手机上愉快地聊天了，但请务必注意：你的机器人之所以能回消息，是因为你电脑（或服务器）里的 Docker 容器正在后台努力工作。 如果你关掉了刚才运行命令的终端窗口，或者你的电脑处于关机/休眠状态，机器人就会因为失去后台支撑而“断线”无法回复。如果你希望实现 24 小时不间断的智能服务，建议后续将该服务迁移并部署到永不关机的云服务器上。
