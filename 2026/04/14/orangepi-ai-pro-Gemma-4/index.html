一 挂载 U 盘与扩充虚拟内存 Swap

由于本地跑大模型非常吃内存，板载的 8G 往往不够用，我们首先需要利用外置 U 盘来扩容虚拟内存（Swap），防止编译或运行过程中因 OOM（内存溢出）而死机。

1.1 挂载 U盘

  • lsblk：查看系统所有块设备（磁盘）列表
    在进行格式化或挂载操作之前，我们必须先确认 U 盘在系统里的“身份”。执行这个命令会列出所有连接到板子上的存储设备，通过容量大小（比如 32G、64G）可以很容易分辨出哪个是你的外部 U 盘，通常显示为 /dev/sdb 或 /dev/sdc。请务必核对清楚，防止误删了系统盘。

  • sudo mkdir -p /mnt/usb sudo mount /dev/sdb1 /mnt/usb：创建 U 盘挂载目录和挂载。

1.2 扩充虚拟内存 Swap

  • sudo fallocate -l 8G /mnt/usb/swapfile：快速预分配 8GB 虚拟内存空间。
    大模型（如 Gemma-4）编译和运行都极其吃内存，板载内存不够时极易死机。fallocate 命令相比传统的 dd 方式可以瞬间完成空间分配。这相当于在 U 盘里划出一块 8GB 的地盘专门给系统当“应急内存”使用。
  • free -h：检查内存空间

  • cd /mnt/usb：进入U盘

二 llama.cpp 搭建

点击前往百度网盘下载 (提取码: gy68)
  • unzip llama.cpp.zip：在/mnt/usb解压我们的文件夹。

三 模型下载

  • gemma-4-E2B-it-Q4_K_M.gguf：在/mnt/usb上传我们的模型文件。

四 编译模型与运行推理测试

4.1 解决一些兼容问题，否则CPU跑步起来

  • cd llama.cpp：进入到我们的文件夹。

昇腾RmsNorm算子禁用
在判断是否支持该算子的地方，强行插入 return false;

4.2 编译模型

  • cd llama.cpp：进入到我们的文件夹。

确保环境变量生效

  • cmake --build build --config Release -j4：编译我们模型。

4.3 运行推理测试

  • cd /mnt/usb/llama.cpp/build/bin：进入编译生成的二进制文件目录。
    在之前的编译步骤顺利完成后，llama.cpp 会把所有生成的可执行工具（例如我们之后要用到的核心推理程序 llama-cli）统一存放在 build/bin 文件夹下。我们需要先切换到这个目录，才能准备加载模型并正式开始“调戏”大模型。
